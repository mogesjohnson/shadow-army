# Unit M1, round 1, batch M1-V6 (where soldiers run, instructions, roster, CI)

## R-M1-23

- severity: P1
  type: contradiction
  location: M1 Implements (docs/spec/v2.md:536-544); CH-1 (docs/spec/v2.md:217)
  claim: The M1 text never says where a soldier runs or that a guard watches it. Settled decision 7 (a throwaway snapshot of HEAD) and the settled rule that auto or full needs the guard are both missing, and WSP-1 and WSP-4 wait for M6.
  scenario: The shipped shadow.config.json sets claude-sonnet to `auto`. CH-1 says to open "a session in a worktree", but no worktree exists before M6. Reading A: the session opens in the folder itself, and Iron edits the owner's uncommitted files with nothing to detect it. Reading B (the draft): a snapshot of HEAD, plus a guard on both the checkout and the snapshot. Any change fails the turn and marks the soldier down. The text also doesn't say whether a write in the snapshot is allowed, discarded or a read-violation, or whether the snapshot is deleted or kept (PO-7 keeps "worktrees").
  evidence: settled.md, M1 decision 7 and the design rule "With auto or full, a read-only task runs in a throwaway snapshot, and the checkout guard fails any task…". In section 4, "snapshot" appears only for agy (ARM-6, :384-387). Draft: src/v2/postOffice.ts:128-130 and :202-222.
  fix: In M1 and CH-1: "Until WSP-1 (M6), each session opens in a throwaway snapshot of HEAD under `.shadow/v2/`. The checkout guard covers each turn, as ARM-6 gives agy. A change to the snapshot or the checkout fails the turn as a read-violation." Add an M1 AC for it. decision: the snapshot is removed at close, or kept until the owner clears it.

## R-M1-13

- severity: P2
  type: readiness
  location: PO-1 (docs/spec/v2.md:165-167); M1 Implements (:536-544); M1-AC4 (:551)
  claim: M1 builds PO-1's crash restart, but the pieces that define its outcome come later. How the crashed turn ends is PO-8 (M2), how its message ends is MSG-4 (M3), and what a restart reopens is CH-9 and SI-4 (M4). Settled decision 7 isn't in the text either. So M1's crash path has no defined outcome.
  scenario: (1) claude writes `result` and exits, and the exit is noticed before the last bytes of its output arrive (they come through separate pipes). Without PO-8's "reads everything the CLI wrote before it decides", M1 calls a finished turn cut short, or misses claude's crash result. (2) The restart opens a brand-new claude session with no history (there is no `--resume` before M4). It runs in the same snapshot, which still holds the crashed turn's partial edits. The next brief runs on edits its own session never made (simulation 4), and nothing tells the owner the soldier forgot. (3) If `rules.md` or Iron's `model` was edited before the crash, whether the restart rebuilds the instructions and the model (simulation 5) is undefined until SI-4. (4) CH-1 opens a session "in a worktree", but WSP-1 is M6. Where an M1 session runs, and whether its snapshot is kept, is written only in settled.md.
  evidence: :167 "Before the channel restarts, that turn is finished as PO-8 says", but PO-8 is M2 (:187, :561). CH-9 (:260) and SI-4 (:278-281) are M4. Settled decision 7 reads "M1's soldiers run in a throwaway snapshot of HEAD, until WSP-1 gives each its worktree in M6". The only snapshots the spec mentions are ARM-6's and the screen snapshots. M1-AC4 (:551) checks only that the message isn't sent again.
  fix: "M1: Soldiers run in a throwaway snapshot of HEAD, one per session, kept after close (PO-7). M1 implements PO-8's 'cut short' rule for claude: it reads all of the CLI's output before deciding whether `result` came. Until CH-9 (M4), a restart opens a new session in a new snapshot, with the instruction text and settings the first session started with, and the soldier's log says 'restarted: new session, history not kept'." M1-AC4 adds the case where the exit is noticed before the output. (A new snapshot or the same one: decision.)
