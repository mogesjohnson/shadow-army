- **PO-5** (M1; U, F) **Logs.** The post office keeps an append-only log for itself and one for each soldier's session, under `.shadow/v2/logs/`. Logs are JSON Lines: one file per soldier session, named by the soldier and the session id, and one per start of the post office, named by its start time. Every write passes through `redact()` (WSP-8).
  - A log holds each message, thinking block, tool call and tool result whole. The fragments a CLI streams are joined first, and `redact()` runs on the joined text. When a turn ends before a message is whole, what was joined so far is written.
  - Each decision (HOST-14, →M5) is logged when it opens and when it closes, so a post office ended outright loses none.
  - A log never stops a soldier or a turn. A write that fails is tried once more. If that fails too, the post office carries on, reports it once on the event stream, and Claude's transcript gets one line, as in `Shadow Army: logs not written · disk full`. Each later write tries again, and the first line written after a gap says how many lines were lost. A line cut short by a failed write is ended before the next one, and a reader skips any line that doesn't parse.
