R-F-72, R-F-73 (c), R-F-74 (b): which strings are IDs, which requirements rule 9 checks, and a test's kind.
<<< OLD

=== NEW
Each test names the requirement or AC IDs it verifies, in its title or a comment beside it. An ID has one of this spec's prefixes (HOST, PO, CH, SI, MSG, SES, ARM, WSP, SEC, VIS, SET, OBS, VER, LEG), or the form `Mn-ACn`; other text, such as `UTF-8` or `SHA-256`, is no ID. A committed file, `docs/spec/implemented.txt`, gives the milestone being built and the requirements implemented so far; each PR adds those it implements, and removes none. The script also fails when a requirement that file lists, or one of an earlier milestone than the one it gives, with U, C, I, X, F or S evidence, is named by no test, or when a test names an ID this spec doesn't have. So a milestone built over several PRs is checked on each of them. The script doesn't check a test's kind: the PR's AC-to-evidence mapping (section 6) says which test gives which kind of evidence, and the PR reviewer checks it. R and L evidence is recorded on the PR (VER-8 and section 6).
>>> END
