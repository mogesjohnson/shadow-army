R-M1-141 (a): PROCESS_CREATE_PROCESS, the threads and the token's default DACL.
<<< OLD
`PROCESS_CREATE_THREAD`, `PROCESS_DUP_HANDLE`, `WRITE_DAC` or `WRITE_OWNER`, and that holds an OWNER RIGHTS (`S-1-3-4`) entry, which takes away the owner's implicit right to change the DACL back. A handle opened before the change keeps its rights, as Claude Code's handle to the process it started does. Where the DACL can't be set, the log says `memory protection: none` with the reason, and the post office goes on.
=== NEW
`PROCESS_CREATE_THREAD`, `PROCESS_CREATE_PROCESS`, `PROCESS_DUP_HANDLE`, `WRITE_DAC` or `WRITE_OWNER`, and that holds an OWNER RIGHTS (`S-1-3-4`) entry, which takes away the owner's implicit right to change the DACL back. Without `PROCESS_CREATE_PROCESS`, no process can start a child with the post office as its parent. The same operation gives each of the post office's threads a DACL that grants no one `THREAD_SET_CONTEXT`, `THREAD_GET_CONTEXT`, `THREAD_SUSPEND_RESUME`, `WRITE_DAC` or `WRITE_OWNER`, with the same OWNER RIGHTS entry, and sets the default DACL of its token to it, so a thread it starts later gets it too. A handle opened before the change keeps its rights, as Claude Code's handle to the process it started does. Where the DACL can't be set, the log says `memory protection: none` with the reason, and the post office goes on. A thread whose DACL can't be set is named in the log line, as in `memory protection: process DACL · 1 thread open`.
>>> END
