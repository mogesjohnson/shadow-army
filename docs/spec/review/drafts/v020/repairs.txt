<<< OLD
  - It needs Windows 10 or 11, or Windows Server 2016 or later.
=== NEW
  - **Smart App Control.** Windows 11's Smart App Control runs on App Control's engine. When it is on, it blocks code that is unsigned and that Microsoft's cloud doesn't know, DLLs and some scripts included; it has no exception for one app and takes no hash rule. The script and its DLL are unsigned and new with each release, so Smart App Control either makes PowerShell run the script in ConstrainedLanguage mode or blocks the DLL; spike S7 says which. Either way the check fails (PO-14), and no soldier starts on that PC. Its state is the `VerifiedAndReputablePolicyState` value under `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy`: 0 off, 1 on, 2 evaluation. In evaluation it blocks nothing, but it can turn itself on later, so a PC where soldiers ran can refuse them afterwards. When the script refuses, or the DLL fails to load, the script reads that value, and at 1 PO-14's message names Smart App Control. The remedy on that PC is turning Smart App Control off, since signing is a non-goal of v2.0 (section 1). GitHub's Windows x64 runners run Windows Server, which has none; S7 records the value on each Windows runner. The owner's PC has it off (2026-10-27), so nothing there tests it. S7's result replaces this paragraph's unknown.
  - It needs Windows 10 or 11, or Windows Server 2016 or later.
>>> END
