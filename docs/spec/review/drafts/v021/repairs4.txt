R-M1-221: CH-4, grok's permission mode on its command line.
<<< OLD
  - Usage comes from the prompt result's `_meta.usage`.
=== NEW
  - Usage comes from the prompt result's `_meta.usage`.
  - It passes the permission mode of the soldier's autonomy on every start and resume, as v1 does (`src/adapters/grok.ts`), as `grok agent <flags> stdio`: `--permission-mode plan` for supervised, and from M6 the mode CH-11 sets for a writing turn; `--permission-mode auto` for auto; and `--always-approve` for full. xAI documents that a mode on the command line overrides, for that process, the `permission_mode` default in the user's `~/.grok/config.toml` (https://docs.x.ai/build/features/permissions). So a supervised soldier asks through `session/request_permission` (CH-6, →M2) even where the owner's own grok sessions always approve: under `permission_mode = "always-approve"`, a grok 1.0.70 started with no mode sent no request and wrote at once (probe P-1). This changes one vendor default and disables no safeguard (CH-7). The adapter never sets `_meta.yoloMode` and never sends `/always-approve`, which xAI documents as a toggle. Only an administrator's `disable_bypass_permissions_mode` outranks the flag, and it only takes always-approve away. A contract fixture recorded with the user config at `permission_mode = "always-approve"` shows a supervised session's write and shell command each arriving as `session/request_permission`, and an `auto` session running in auto, not always-approve, before M2 ships grok (section 5.1, C; VER-4).
>>> END
