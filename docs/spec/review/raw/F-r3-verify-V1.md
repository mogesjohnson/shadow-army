- id: R-F-143
  verdict: CONFIRMED
  severity: P2
  evidence: CH-1 :473 (1ba37b5 :474) gives only an absolute PATH entry and no search of the current folder. CH-2 (1ba37b5 :485) knows the `.cmd` shim only for the instructions file. M1-AC10 (1ba37b5 :1064) tests which directory wins, not which file. PO-9 (1ba37b5 :311) requires the guardian to start "exactly the program, arguments ...". Node.js says .bat/.cmd files need a shell (https://nodejs.org/api/child_process.html#spawning-bat-and-cmd-files-on-windows), and since CVE-2024-27980 spawning one without a shell fails with EINVAL. npm puts an extensionless sh `claude` beside `claude.cmd` and `claude.ps1` in the same folder. Codex's draft (AIConnections-m1/src/v2/processTree.ts:386) tries "" before PATHEXT, which would pick that extensionless file. At :403 it escapes "for both passes, as cross-spawn does". v1 got this from execa/cross-spawn (src/adapters/exec.ts:20, :58). No ledger row covers it: R-M1-2 is about which directory, R-M1-43 about the instructions file.
  reason: The order of lookup within a folder, and how a `.cmd` CLI is started and quoted through cmd.exe, are left to each implementer. Codex's draft already shows a wrong order, and cmd.exe re-reads config-derived arguments such as `--model` and the inline `--settings` JSON.
  fix: Add to CH-1: "On Windows, a name is looked up in each absolute `PATH` entry with each extension of `PATHEXT` in order, never with none, and the first match wins. A `.cmd` or `.bat` CLI is started through `cmd.exe /d /s /c`, with every argument escaped for both `cmd.exe` and the program's own parser, as cross-spawn does; an argument with a line break goes through a file, as CH-2 does for the instructions. The unit test covers the escaping, and M1-AC10 a folder that holds `claude`, `claude.cmd` and `claude.exe`."
