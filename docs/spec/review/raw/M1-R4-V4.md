- id: R-M1-236
  verdict: NEEDS-PROBE
  severity: P2 (kept). The outcome is safe: containment ends every tree and PO-1 recovers. But when the host kills the post office at exit, PO-7's headline promise fails, and the next start runs crash recovery.
  evidence: |
    - PO-7 261 promises a close "through that CLI's own exit" with no condition. 263 lists three triggers and no signal. 266 says the release must arrive within `session.end`'s "short time budget". https://code.claude.com/docs/en/plugins/mods/reference.md#limits puts all `session.end` hooks together at 1.5 s. The shutdown at 279-281 can take up to 30 s plus 10 s. 274 already states the outright end, "for example by Claude Code when the mod unloads", and routes it to PO-1 and PO-16's containment. decisions.md 58 records from the d.ts that "a spawned child is killed when the module unloads".
    - Partly refuted. The "no defined way to finish the shutdown" claim fails, because 274 together with PO-1 220-227 defines the outright-end path. The terminal-close case fails for soldiers, because guardians run "in a session and process group apart from the post office's" (PO-10 320), so a SIGHUP to the foreground group doesn't reach the CLIs. M1-AC8 1083 ("as HOST-2 and PO-7 say") passes under 274 either way, though it doesn't pin which path a normal exit takes.
    - Still real: 261 is unconditional; 263 has no rule for a termination signal; and with Node's defaults a SIGTERM or SIGHUP ends the post office with no logged reason and no lock release (https://nodejs.org/api/process.html#signal-events). On Windows, Node's `subprocess.kill()` ends the child "forcefully and abruptly" whatever the signal (https://nodejs.org/api/child_process.html#subprocesskillsignal), so nothing can be caught there.
    - The public mods docs (api.md, events.md, reference.md) don't say how, or whether, the host ends a spawned child at exit or at unload. Only a live run settles it.
  reason: Whether a normal exit can ever reach PO-7's graceful shutdown depends on how the host ends a spawned child (which signal, an uncatchable kill, or none) and on how long after `session.end` it does so, which only a live run shows. After P-17 this becomes a choice between the reviewer's options.
