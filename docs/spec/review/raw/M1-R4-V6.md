- id: R-M1-242
  verdict: CONFIRMED
  severity: P2
  evidence: Snapshot line 251 (PO-5 names files "by the soldier and the session id" and "by its start time" with no format), 254 (new files are created with `O_EXCL`), 504 (CH-2 writes the instructions file "beside the session's log" before the process starts). The snapshot has no rule that gives a session id before the CLI starts or fixes a time format (grep "session id" finds nothing that does). `--session-id` exists for claude (https://code.claude.com/docs/en/cli-reference, per the packet; I did not fetch it).
  reason: A log name that needs a vendor-reported session id cannot exist before the process starts. An unspecified time format can be an illegal Windows file name, or collide at the same second for M1-AC1's racing starts, so one start would fail `O_EXCL`. I take the post-office-made id over claude's `--session-id` because codex and grok report their ids only after they start, so a claude-only rule leaves them unsolved.
  fix: |
    OLD (PO-5, line 251): one file per soldier session, named by the soldier and the session id, and one per start of the post office, named by its start time.
    NEW (PO-5, line 251): one file per soldier session, named `<soldier>-<log id>.jsonl`, and one per start of the post office, named `po-<UTC start time as YYYYMMDDTHHMMSS.mmmZ>-<pid>.jsonl`. The log id is a UUID the post office makes before it starts the CLI. The CLI's own session id, when it reports one, goes on the log's first line after it, and the log keeps its name. Where a CLI takes an id on its command line, as claude's `--session-id` does, the adapter passes the log id.
    CH-2 line 504 needs no change except "beside the session's log" now has a name at that time.
    Reviewer's note: the packet's fix sets the claude id equal to the post office's and does not cover codex or grok, so use the NEW above. If the owner would rather claude's `--session-id` be the one name, that is a product choice, but this form is safe either way.
