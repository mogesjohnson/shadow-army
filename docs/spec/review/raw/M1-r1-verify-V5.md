- id: R-M1-12
  verdict: CONFIRMED
  severity: P1
  evidence: Snapshot CH-2 226 ("The turn totals come from `result`"); M1-AC3 548 ("turn usage parsed"); VER-9 514; SES-7 371, OBS-3 446 and HOST-15 157 add per-turn figures but give no rule for them. https://code.claude.com/docs/en/agent-sdk/cost-tracking: under "Track costs in streaming input mode", `usage` "covers only that turn, and within it only the main agent loop"; `total_cost_usd` and `modelUsage` "carry the running total for the whole call so far, plus any spend restored when the call resumed a session". Under "Recover totals after a session crash", the final `error_during_execution` result "may carry zeroed `usage`, `total_cost_usd`, and `modelUsage`". Also: "Per-step `output_tokens` is a placeholder", and the figures are "client-side estimates". https://code.claude.com/docs/en/agent-sdk/typescript (SDKResultMessage): `usage` is "main agent loop only … per-turn in streaming-input sessions"; `total_cost_usd` is "cumulative". s6-results.md line 7 (an interrupt result's usage is all zeros) and line 22 (the rule planned for the spec). #63 comment 6159653512 plans "Usage as each turn's own figures, never running totals" for v0.6; the snapshot doesn't have it. The archived 2.0 draft had the rule (F20 line 227; LEDGER-4 line 719). Duplicates already recorded: R-M1-30, R-F-20.
  reason: Nothing turns claude's running totals into one turn's figures, so either reading of "turn totals" is wrong: running costs get added up, or subagent work and stopped or crashed turns are lost. M1-AC3 passes under both readings.
  fix: Replace CH-2's last sentence with this bullet. "- **A turn's own figures.** claude's `result` gives `usage` for the turn's main loop only. Its `total_cost_usd` and `modelUsage` are running totals for its process, subagents included, plus the earlier spend of a session it resumed. A turn's tokens, by model, and its cost are its result's `modelUsage` and `total_cost_usd` less those of the result before it. That is: nothing, for a new session's first turn; the previous result in the same process; or, for the first turn after a resume (CH-9, →M2), the last result of the process before it, if that process exited normally. With no such result, the turn's cost reads 'not reported' and its tokens are its main-loop ones. Those are input and cache summed over its main-loop assistant messages, each message id counted once, and output from its `usage`, since an assistant message's output count is a placeholder. A result whose `usage`, `total_cost_usd` and `modelUsage` are all zero, as after a crash or a stop (spike S6), reports nothing. That turn's input and cache are summed the same way, its output and cost read 'not reported', and it is never the result before the next turn. The cost is claude's own estimate. SES-7, HOST-15 and section 5.1's live checks add these turn figures, never running totals." M1-AC3: the recording has three turns, and their figures add up to the last result's `modelUsage` and `total_cost_usd`. M1-AC4: the fake adds a crash mid-turn, whose zeroed result reads 'not reported' and changes no other turn's figures. The proposed fix misses the resume case: "the previous result from the same process" leaves the restored spend in a resumed process's first turn.
  v0.7: §5.1 L's measure (line 564) now rules out running totals for the parity check. But CH-2 line 255 still says "The turn totals come from `result`", and nothing names which of claude's fields are running totals; SES-7 (400), OBS-3 (508) and HOST-15 (184) are unchanged. That measure also has two new problems for claude. Counting output "one by one" per request reads the placeholder counts. And the headless `--output-format json` run gives no per-request ids, while its `--resume` follow-up "reports the conversation's whole total, earlier runs' spend included" (https://code.claude.com/docs/en/headless, under "Pipe data through Claude").
