- id: R-M1-161
  verdict: CONFIRMED
  severity: P1 (as given). Part of the claim is wrong, part is worse than stated. The forged-log half mostly fails: WSP-10 already leaves out every working tree that isn't this army's, so a log claiming ownership gains nothing against the metadata check, and a fabricated dead turn has no soldier change to hide. The link half is worse: through a directory a co-resident user owns, that user can swap or plant files beside the logs. That means planting log files the post office then appends to, linking `.gitignore` to an owner file so PO-5's write clobbers it, and from M3 replacing the `--mcp-config` file, whose stdio server command claude runs as the owner. It needs a hostile repo and a hostile local user together, but Appendix D names both as untrusted actors and promises the army's files are "the owner's alone (PO-5)".
  evidence: v2@02d5f84 PO-5 lines 243-244. Unchanged in v0.15 (v2@8e45853 lines 243-244), so it is neither fixed nor moved. Other v0.15 lines: WSP-3 742 (M6, and it covers only deleting or reverting through a link, never writing, so even M6 doesn't cover this); PO-1 204-205 (the lock is in "the folder" and only proves liveness, not where the files live); PO-1 215-216 and 220 (recovery reads the last one's logs, and removes "any instructions or settings file the last one left beside its logs"); WSP-10 767 ("this army's own ... when this army's logs name it (PO-5)"; other working trees' metadata is "neither compared nor trusted"); CH-2 476 and 484 (the instructions and `--settings` files sit beside the logs when the command line can't carry them); PO-4 236 (M3 `--mcp-config` file beside the log); ARM-7 712-715 (the trust card covers only top-level policy files and `.mcp.json`, never `.shadow/`, and a repo without policy files raises no card); Appendix D 1753 (actors row) and 1785 (residual 5). No ledger, settled.md or ADR entry covers the army's own folder being a link: the only ledger hit for "symlink" is R-M1-161 itself, ADR-0013 line 15 carries over only v1's "link safety", and R-F-100 fixed only modes. Legacy 2.0 SAFE-8/9/12 cover deleting and reverting only. Git: "The default is true ... If false, symbolic links are checked out as small plain files" (https://git-scm.com/docs/git-config, core.symlinks). So Linux and macOS clones recreate a committed `.shadow` or `.shadow/v2` link. Git for Windows "disables support for symbolic links by default", and creates real links only with core.symlinks=true plus the "Create symbolic links" right or Developer Mode, on NTFS or ReFS (https://gitforwindows.org/symbolic-links.html). Note: a hostile repo can also commit plain tracked files under `.shadow/v2/logs/` with no link at all. `.gitignore` doesn't untrack them, and M1-AC2's `git status --porcelain` check doesn't show unchanged tracked files. So the forged-log input to PO-1 also exists without a symlink.
  reason: Nothing in M1, not PO-5, the PO-1 lock, ARM-7, WSP-3 or PO-21, stops the post office from creating, narrowing or writing its logs and side files through a link, or into a folder another user owns, that a cloned repository put at `.shadow` or `.shadow/v2`. That breaks PO-5's owner-only promise, which Appendix D's actors row and residual 5 rely on.
  fix: In PO-5, add after "The owner's alone": "**Its own folders.** Before it writes anything, the post office checks `.shadow/`, `.shadow/v2/`, `~/.shadow-army/` and each folder it makes under them (`logs/`, `trees/`, `reports/`, `snapshots/`, `trust/`): each must be a plain folder, not a symbolic link or, on Windows, a junction or other reparse point, and must be owned by the owner's user. It creates each file it writes there new, and never follows a link to it (`O_NOFOLLOW` and `O_EXCL` on Linux and macOS; no reparse point on Windows). It also checks that git tracks nothing under `.shadow/v2/`. If any check fails, no soldier starts and nothing is written there; the mod says why, as in `the army's folder .shadow/v2 is a link, not a folder of yours`." In Appendix D's actors row, cite the new sentence beside PO-5. Add to M1-AC2 an X case: with `.shadow` and then `.shadow/v2` each a committed symbolic link (a junction on Windows) to a folder outside the checkout, with a `.shadow/v2` owned by another user (faked), and with a tracked file under `.shadow/v2/logs/`, no soldier starts, the mod gives the reason, and nothing is written at the link's target.
