- id: R-M1-167
  verdict: DECISION
  severity: P1
  evidence: The current spec has the same text, about one line lower than in v2@02d5f84: PO-19 v2.md:436 ("A Group Policy execution policy still overrides `Bypass`"), 440 (only ConstrainedLanguage is handled; "the DLL isn't" signed); PO-13 354 ("A file that has changed is refused"); PO-14 361-366 (no message for this cause); PO-3 230 (DACL fails, so `memory protection: none`, and the post office goes on); M1-AC15 1096 (AllSigned at the user scope only); M1-AC18 1111 (AppLocker only). §1's non-goals (48-54) leave nothing out. settled.md has nothing on it. D-3 (decisions.md:84, 114, 124) settles AppLocker/App Control allowance "by hash or publisher", not the execution policy. https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1 says of `-ExecutionPolicy`: "it doesn't take precedence over the execution policy set by using a Group Policy". "If you disable Turn on Script Execution, scripts don't run." "Allow only signed scripts" = AllSigned, which "Requires that all scripts ... be signed by a trusted publisher". The same page says the policy "isn't a security boundary". Signing a .ps1 writes a signature block into the file, so its SHA-256 changes.
  reason: The scenario is real on any machine whose Group Policy sets AllSigned or Restricted: no Windows soldier starts, no message fits, the administrator's natural fix (signing) trips PO-13's checksum, and the AC tests only the scope that `Bypass` overrides. It fails closed, so P1, not P0. The fix needs either a paid certificate or a stated unsupported fleet, and that is the owner's call.
  options: (a) PO-20's release workflow Authenticode-signs the script and the DLL with a project certificate (a recurring cost, like PO-18's Apple ID) before checksumming. PO-13's SHA-256 and SHA256SUMS then cover the signed bytes. PO-14 gains a message naming Group Policy AllSigned/Restricted and Trusted Publishers. M1-AC18 adds MachinePolicy AllSigned and Restricted cases, set through HKLM\SOFTWARE\Policies on a runner. (b) A stated non-goal: Windows machines whose Group Policy sets AllSigned or Restricted run no soldier, with that PO-14 message and an M1-AC18 case. Either way PO-14 step 1 must name this cause. (c), rejected as a side option: run the guardian from the DLL through `-Command`, which the execution policy doesn't govern. It defeats an administrator's control and breaks PO-19's "no code sits in a string".
  big or technical: big (money for a code-signing certificate, and which managed fleets are supported).

Appendix D row 9 reads "Each CLI, git and the post office's Node.js start from an absolute path found on `PATH` alone (CH-1, WSP-10, HOST-2)", and adds HOST-2 to its tests column.
