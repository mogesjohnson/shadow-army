### The P1 repairs

- **R-M1-161: FIXED.**
  - Evidence: PO-5 248-249, M1-AC2 1044, Appendix D actors 1765.
  - Every folder the army writes in (`logs/`, `trees/`, `reports/`, `snapshots/`, `trust/`) must be a plain folder owned by the owner, and the check runs before any write. Files are created new with `O_EXCL`, and git may track nothing under `.shadow/v2/`.

  - Evidence: HOST-2 116-117, M1-AC10 1074, row 9 1779.
  - The mod passes the absolute path it found as argv[0]. The mod API has what this needs: `$.env.get` and `$.fs.stat/exists` (mod-api-2.1.294/claude-code.d.ts 3240, 3560-3570), and `$.process.spawn` takes argv (3496).

- **R-M1-169: FIXED for npm installing from the public registry or from a tarball; not fixed for mirrors or other installers (new finding N3, P2).**
  - Evidence: PO-13 357, PO-21 468-469, M1-AC17 1119.
  - PO-13, PO-20 and PO-21 agree. PO-20's attested tarball carries the shrinkwrap's integrity hashes, and PO-21 and M1-AC17 test the pinned version.
  - The pinning does not hold everywhere:
    - pnpm ignores npm-shrinkwrap.json (https://pnpm.io/limitations).
    - npm ignored a package's shrinkwrap when the registry does not set `_hasShrinkwrap`. That covers Verdaccio, Artifactory, GitHub Packages and GitLab (https://github.com/npm/cli/issues/4583). The issue was closed 2026-04-21 via PR #9262. Which npm release carries the fix, and whether Node 22's bundled npm 10 does, is unverified.
    - PO-13 356 explicitly supports "a mirror".
  - It also depends on open card D-28 (how the mod and the package install together).

- severity: P1
  type: gap
  location: CH-1 (docs/spec/v2.md:480), M1-AC10 (:1074), Appendix D row 9 (:1779), PO-18 (:426-431)
  claim: On Windows a `.cmd` CLI started through `cmd.exe /d /s /c` in the soldier's snapshot runs a repository's committed `node.exe`, `node.bat` or `node.cmd`, because cmd.exe searches the current folder before PATH and npm's shim runs `node` by name; CH-1 also never says how cmd.exe itself is found.
  scenario: claude installed with npm (or codex, which ships on npm, from M2) gives `%APPDATA%\npm\claude.cmd` with no node.exe beside it, so the shim sets `_prog=node`.
