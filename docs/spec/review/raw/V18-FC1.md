**N1** (P2) PO-4 250, PO-1 217, Q9 1399, M3-AC8 1235
- **What is wrong.** PO-4 250 says the post office "reads that setting from the managed settings Claude Code reads". The post office can't do that. Claude Code takes managed settings from files, MDM, a `policyHelper`, and the claude.ai admin console. Admin-console settings are fetched over the network at startup and cached in `~/.claude/remote-settings.json`, and PO-2 forbids Shadow Army network calls. "All settings available in settings.json are supported except those restricted to OS-level policy delivery" (https://code.claude.com/docs/en/server-managed-settings). The page lists `disableSideloadFlags` as also rejecting `--mcp-config` (https://code.claude.com/docs/en/plugins/mods/admin). Reading the setting ourselves also rebuilds vendor logic, against the thin-orchestrator rule. No AC tests the case.
- **Scenario.** A Team org sets `disableSideloadFlags` in the admin console. From M3, the post office finds no setting in files or the registry, so it starts claude with `--mcp-config`. Claude exits with its sideload refusal. PO-1 217 treats this as a refused start: the soldier is down, with "Kaisel can't start at supervised: your organization's managed settings refuse it · lower its autonomy". That is exactly what 250 says must never happen.
- **Fix.**
  - At 250, replace "Before it starts a claude soldier, the post office reads that setting from the managed settings Claude Code reads. Where it is set," with: "The post office doesn't read managed settings itself. When claude exits before its first event with its `disableSideloadFlags` refusal of `--mcp-config`, known by its message as section 5.1 C's fixtures record it, that start is not a crash and not PO-1's refused start: the post office starts the soldier again at once, and starts its later claude sessions the same way until it restarts. Then".
  - At 217, append: "A refusal of `--mcp-config` under `disableSideloadFlags` is handled as PO-4 says, never with this line."
  - At 1235, append: "A fake claude that exits with the recorded `disableSideloadFlags` refusal of `--mcp-config` is started again without it, and without `send` unless it takes `send` over its stream-json input; it isn't restarted as a crash, and its log and row say why (PO-4)."

**N2** (P2) WSP-11 794, M1-AC11 1105
- **What is wrong.** "Every folder above it must be … writable by no other user." By default, the root of every NTFS drive lets Users create subfolders: C:\ grants Users `(CI)(AD)` and `(CI)(IO)(WD)` (STIG baseline, https://stigviewer.com/stig/microsoft_windows_server_2022/2024-02-27/finding/V-254251). Read literally, every value on a Windows drive fails. That includes the `%LOCALAPPDATA%` folder the same paragraph tells roaming-profile machines to use, which was D-29's reason for the variable. The same exposure at the drive root already applies to the default folder and to the checkout itself.
  - Separately, the list of files checked leaves out `.claude/AGENTS.md`. Claude reads "every AGENTS.md and .claude/AGENTS.md in your working directory and the directories above it" (https://code.claude.com/docs/en/memory).
  - M1-AC11 tests only the folder itself, never a parent folder that others can write.
- **Scenario.** A Windows owner sets `SHADOW_ARMY_SNAPSHOTS=%LOCALAPPDATA%\shadow-army\snapshots`, as WSP-11 advises. C:\ fails the check, and no soldier ever starts.
- **Fix.**
  - At 794, after "writable by no other user", insert: "; on Windows, no user or group but the owner, SYSTEM and Administrators holds `FILE_ADD_FILE`, `FILE_DELETE_CHILD`, `DELETE`, `WRITE_DAC` or `WRITE_OWNER` on it. The right to create a subfolder alone, which every Windows drive's root grants its users, passes, since the checkout's own drive has it too".
  - At 794, change the file list to "`CLAUDE.md`, `CLAUDE.local.md`, `.claude/CLAUDE.md`, `AGENTS.md` or `.claude/AGENTS.md`".
  - At 1105, add: "a folder whose parent another user can write (faked) starts no soldier; on Windows, a folder under `%LOCALAPPDATA%` starts one".

- **Fix.**

  - At 458, after "turning Smart App Control off", add: ", which on older Windows 11 builds can't be undone without a reset; S7 records the build it tested".
