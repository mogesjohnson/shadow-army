### R-F-171: DECISION (P2)
- **Already covered, so that part is REFUTED:** M1-R4-V1b's side point, and the M1 case. Residual 14 at 1859 says it: "So does a filter a soldier added that held harness git in M1, once the post office restarts: … the restart trusts the config as it then is, and the held turn's guard, which the next post office finishes, runs it too." The R-F-56 decision settles filters set at start as the owner's.
- **Not covered: from M2.**
  - WSP-10 797 trusts "their state when the post office started, or as the owner last accepted it".
  - WSP-10 798 says only "n keeps it held". Nothing keeps the hold across a restart.
  - PO-1 225 keeps an unanswered card in the records, but nothing re-raises it.
- **The result:** a config change the owner refused with `n`, or never answered, is trusted at the next start (a Claude Code restart, a crash, or a reload). PO-1 228 then runs the held turn's guard through harness git, which runs that soldier's `filter.*` driver.
  - A clean filter is arbitrary code, run as the owner. It can rewrite the checkout file, or the baseline, which has no hash (residual 12), before the guard reads it.
  - So the guard can be defeated while it checks the very turn that planted the filter.
- **Severity:** P2, not P1. The guard is detection only, and a soldier at `auto` that runs code already has residual 3. But this undoes an explicit `n` from the owner, which nothing states.
- **Options:**
  - (a) **Keep the hold across restarts.** WSP-10 logs the trusted state's hashes at start and at each `y`. A start whose last log records a hold with no `y` keeps harness git held against that state, and the card shows again from M2. In M1 the hold lifts only once the change is gone. This costs a new on-disk state, and M1 can stay held until the owner reverts by hand.
  - (b) **Trust at restart, but finish held items without the soldier's filters.** This also needs the last trusted state, so it is (a)'s cost plus a guard path with filters neutralized. Baselines taken with the owner's filters would then compare oddly.
  - (c) **Accept and state it.** Use this OLD/NEW:
    - WSP-10 798, OLD: `y trusts the state shown, and harness git goes on; n keeps it held.`
    - NEW: `y trusts the state shown, and harness git goes on; n keeps it held until the post office restarts, which trusts the config as it then is (Appendix D, residual 15).`
    - Residual 1859, OLD: `So does a filter a soldier added that held harness git in M1, once the post office restarts:`
    - NEW: `So does a filter a soldier added that held harness git, in M1 or, from M2, one the owner answered n to or left unanswered, once the post office restarts:`
- (c) is the cheapest honest text. (a) is the only one that makes `n` mean what it says.
