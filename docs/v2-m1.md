# M1a base: the post office and Claude channel (Windows only)

This is the transport base of the M1a prototype slice under [#63](https://github.com/mogesjohnson/shadow-army/issues/63): a local post office and a persistent native Claude Code channel. It is the code of PR #75 (`codex/63-m1-post-office`, `04ab953`, written against spec v0.3), cut down to the slice and ported onto `main`. Behavior is as #75 has it. The existing v1 commands continue to work.

Windows only. The slice runs on Windows; macOS and Linux are "Not tested" (D-34). On those systems `spawnManagedProcess` fails with a clear error instead of running containment nobody has checked, and the containment tests skip with that note.

Offline tests use synthetic protocol traffic and a fake `claude` executable (`test/fakes/claude.mjs`). They are not recordings from a real provider. This base has had no live run against a real Claude session.

## Try the persistent channel

Build with `npm run build`. From the target repository, run:

```console
sa live claude-sonnet
```

Type two related prompts. They use the same Claude process and native conversation until you exit. `/stop` interrupts a turn; `/exit` closes the session. When a native approval request appears, enter `/answer <request_id> <native JSON response>`. The adapter forwards that explicit response and never grants approval by itself.

A single task: `sa live claude-sonnet "Read README.md and package.json; describe the project." --json`. The single-task caller closes its post office afterwards.

The soldier works in a private detached snapshot of committed `HEAD` and may read only. A detected write fails the turn and the snapshot remains for inspection. Uncommitted checkout edits and untracked files are not in the snapshot. The snapshot comes from v1's `createSnapshot`; it is Not tested against WSP-10's harness git.

Claude must already be installed and authenticated. Its vendor system prompt, native tools and permissions stay in place. Standing instructions are appended through `--append-system-prompt-file` on Windows and `--append-system-prompt` elsewhere, with the same full text. An oversized instruction set (estimate `ceil(UTF-8 bytes / 3)` of 1,500 tokens or more) fails before launch.

## Launcher, containment and logs

`sa post-office --cwd <repository>` is the internal process boundary. The launcher generates the credential, writes one bootstrap JSON line on standard input and closes it. The credential never goes in arguments, the environment, a temporary file or a log. Commands use loopback HTTP; events return as JSONL on standard output. A normal session ends through the authenticated shutdown command; the helper also ends when its launcher disappears, and the client forces shutdown of a wedged helper.

Each session's Claude runs under a Job Object with kill-on-close and no breakaway. Closing gives the CLI two seconds after stdin EOF to finish its own cleanup, then terminates the job and waits for it to empty. If cleanup cannot be confirmed, close throws. Not tested against v0.27's guardian script with DACLs (PO-19): this is #75's own Windows path.

The post office and each session write append-only JSONL logs under `.shadow/v2/logs/`, redacted before they are written or sent. Token counts come from native usage. Claude's `total_cost_usd` is a client estimate, marked `costSource: native_cli_estimate`, not a billing record.

## Checks

- `npx tsc --noEmit` and `npm test`. `modRelay.test.ts` runs the built relay, so run `npm run build` first (CI does).
- `npm run test:coverage` enforces an 85% line threshold over `src/v2`. Not counted: `main.ts` and `modRelay.ts` (they run only as subprocesses, which v8 cannot see here), `channel.ts` (types only), and, off Windows, `processTree.ts` (Windows-only code, Not tested there). Reasons are in `vitest.config.ts`.
- CI keeps all three systems. On Linux and macOS the containment tests skip and one test checks the clear failure.
